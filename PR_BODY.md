# Milestone M0: Scaffold

Arabic-first Bookshelf Exchange foundation: Next.js 16.4.3 + React 19 + Tailwind v4, next-intl `ar`/`en` routing with server-set RTL, Auth.js v5 split config + JWT credentials (optional Google), Prisma 7.10.1 with the full 27-model/12-enum v1 schema, and a hand-augmented init migration applied to compose Postgres.

## What is in this PR

- **Scaffold** — pinned `next@16.4.3`, React 19.3.1, Tailwind v4 via `@tailwindcss/postcss`, ESLint 9 flat config, Vitest 3, strict TypeScript.
- **Database** — local-only Postgres 17 (`bookshelf_exchange_pg`, `127.0.0.1:5433->5432`), Prisma 7.10.1 with `@prisma/adapter-pg`, global `passwordHash` omission, 27 models / 12 enums, `pg_trgm` GIN title index and five CHECK constraints appended to the init migration.
- **Auth** — `auth.config.ts` (proxy-safe) + `auth.ts` (adapter/credentials/Google-both-or-none), JWT 30-day sessions, `jwt`/`session` callbacks exposing `id`/`role`, bcrypt(12), ACTIVE-only sign-in, DB-backed sliding-window rate limits, same generic error for unknown email and wrong password.
- **i18n / RTL** — `ar` default with `localePrefix: 'always'`, `lang`/`dir` set server-side in the root layout, `x-default=/ar`, 76 mirrored message keys, self-hosted Amiri/Noto Sans Arabic/Fraunces/Newsreader, locale switcher, skip link, mobile menu with Escape/focus return.
- **Pages** — home, loading, error, not-found, sign-in, sign-up, `/api/auth/[...nextauth]`, `/api/health`, all with empty/loading/error handling.
- **Screens** — `docs/screenshots/{ar,en}-{390,1280}.png` captured with CDP device emulation (true 390/1280 viewports; `scrollWidth === innerWidth`, no horizontal scroll).

## Migration note

The init migration is generated by Prisma **and then hand-augmented before first apply** with, in order: `CREATE EXTENSION IF NOT EXISTS pg_trgm`, the `books_title_trgm_idx` GIN index on `lower("title")`, and five CHECKs (`ratings_value_check`, `exchange_ratings_score_check`, `listings_price_cents_check`, `listings_currency_format_check`, `follows_no_self_check`). It was applied once on an empty DB; `migrate status` is green. No `db push`.

## Env note

`.env` is local-only and gitignored; `.env.example` documents every variable. Dispatch naming **`AUTH_GOOGLE_ID` / `AUTH_GOOGLE_SECRET`** supersedes PLAN.md §4's `GOOGLE_CLIENT_*`; the provider is registered only when both are present. Google users get `passwordHash = null`.

## Notes / deliberate deviations

1. **Home is request-rendered, not static.** `site-header` must read the session server-side (`auth()`), which reads cookies; Next 16 therefore marks `/[locale]` dynamic. The contract also forbids extra `next.config` options (`cacheComponents` is off by default), so a static shell would require PPR + Suspense, which the contract does not specify. The hard invariant is met: `next build` succeeds with Postgres down and no page touches the DB at build time. Flagging this contract tension for the reviewer.
2. **`tsconfig.json` adds `"files": ["auth.d.ts"]`.** TypeScript shadows a root `auth.d.ts` that shares a basename with `auth.ts`; the explicit `files` entry (verified with `tsc --listFiles`) keeps the contract's filename without renaming it.
3. **JWT augmentation targets `@auth/core/jwt`**, because NextAuth v5 re-exports (not declares) `JWT` from that module. The session augmentation targets `next-auth`.
4. **`AGENTS.md`** is auto-generated by `next dev` in 16.4.3 and re-created if deleted; committed to keep the tree clean (Next's own guidance). It is not a project hand-written doc.
5. **Production `npm start` needs `AUTH_TRUST_HOST=true`** (Auth.js v5 UntrustedHost protection). Dev, the contract's runtime-smoke path, trusts localhost; `.env.example` documents the variable.
6. **npm audit reports 11 advisories (9 moderate, 2 critical)** in the pinned tree. Not auto-fixed: the contract forbids blind `npm audit fix` and pins the auth/Prisma lines deliberately. Flagged for the dependency review.
